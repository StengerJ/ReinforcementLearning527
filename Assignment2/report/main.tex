\noindent\textbf{Note on supplied code.} The supplied \texttt{furuta\_env.py} is used \emph{unmodified} (a byte-identical copy lives in \texttt{starter/}, and a test checks its hash). It is a balancing task (upright start, termination at $20^\circ$). My wrapper class \texttt{SwingUpTask} (\texttt{hw2/task.py}) uses it only for the dynamics and defines the swing-up episodes around it: downward start, wrapped $\widetilde\theta$, termination only on the arm limit, a five-second success criterion, an explicit \texttt{outcome} field, and the reward $\tfrac12(1+\cos\widetilde\theta)-0.001\tau^2$ ($-10$ on unsafe termination), which is $0$ at the bottom and $1$ upright. The wrapper ignores the raw environment's termination, truncation and reward.

\noindent\textbf{Design fix after a first run.} My first run used the reward $\cos\widetilde\theta-0.001\tau^2$. In that run the mean episode duration fell from about \oldDurFrom{} to \oldDurTo{} steps while the per-step reward stayed near $-0.87$, so the rising return curve was misleading: near the bottom every step was worth about $-1$, so with $\gamma=\cfggamma$ surviving was worth about $-100$ while crashing into the arm limit cost only $-10$, and the agent learned to crash. I therefore shifted the reward (defined in my \texttt{SwingUpTask} wrapper, not in the supplied environment) to be non-negative; all results below use the new reward. (The old-run figures are the only numbers in this report that are not read from \texttt{results/}.)

\section{Environment and episode logic}
\textbf{Supplied environment (unmodified).} \texttt{FurutaEnv.reset()} starts near the \emph{upright} equilibrium: $x=\rawinit$. One step with action 2 ($+0.02$\,N\,m) gave $R_{t+1}=\rawR$ and \texttt{terminated}=\rawTerm. Its \texttt{step()} sets \texttt{terminated} when $|\theta|>\rawlimit^\circ$ (raw, unwrapped $\theta$) or the arm limit is exceeded, so from a downward start ($\theta=\pi$) it terminated after \rawDownSteps{} step(s) with reward \rawDownReward{} ($\theta=\rawDownTheta^\circ$, \texttt{terminated}=\rawDownTerm). It is therefore a balancing task, which is why HW2 swing-up episodes are defined in the \texttt{SwingUpTask} wrapper (\texttt{hw2/task.py}); everything below describes the wrapper.

\textbf{Wrapper (\texttt{SwingUpTask}).} \texttt{reset()} returned $x=\initstate$ ($[\phi,\dot\phi,\theta,\dot\theta]$): the arm is near zero and at rest, and the pendulum hangs near the downward equilibrium ($\widetilde\theta=\inittheta$\,rad, $|\widetilde\theta|\approx\pi$) at rest.

\textbf{Outcomes} ($dt=\dt$\,s, success needs \successsteps{} consecutive steps in $|\widetilde\theta|\le20^\circ$, time limit \maxsteps{} steps): success: \outsuccess; unsafe (arm $|\phi|>\pi$): \outunsafe; time limit: \outtimeout. \textbf{Outside the upright region.} After one step from the start, $\widetilde\theta=\outsidedeg^\circ$ and \texttt{terminated} was false. Stronger evidence: a full episode with zero torque from the downward start ran \zeroSteps{} steps and ended \zeroOutcome{} (terminated=\zeroTerm, truncated=\zeroTrunc), so the pendulum spent the whole episode outside $|\widetilde\theta|\le20^\circ$ without terminating. Terminating there would end every episode on its first step (it starts at the bottom, $\approx180^\circ$ from upright), so the agent could never experience the swinging needed to reach the upright region.

\textbf{Upright counter reset.} In a test episode started upright, the consecutive-upright counter reached \ctrBefore{} steps, and on the step that left the region it was \ctrAfter{} with terminated=\ctrTermExit. After re-entering, it took \ctrReentry{} more steps to finish with outcome \ctrOutcome, so success requires \successsteps{} \emph{consecutive} upright steps, not a cumulative count.

Both targets use the same stored transition ($\alpha=\auditalpha$, $\gamma=\auditgamma$). $Y^{\text{SARSA}}=R_{t+1}+\gamma Q(S_{t+1},A_{t+1})$ and $Y^{Q}=R_{t+1}+\gamma\max_a Q(S_{t+1},a)$; the program output matched the hand calculation (asserted in \texttt{audit\_updates.py}). The two targets are equal when the next action $A_{t+1}$ is a greedy action in $S_{t+1}$ (for example the greedy policy or $\epsilon=0$), and also whenever all $Q(S_{t+1},\cdot)$ are equal (every action is then greedy); they differ when exploration picks a non-greedy $A_{t+1}$.

\textbf{Nonterminal case.} The state index changes from the $S_t$ row to the $S_{t+1}$ row although the step is physically small, because $\widetilde\theta$ crosses the $\pm\pi$ wrap seam: the $\widetilde\theta$ bin goes from \seamFrom{} to \seamTo{} while the other three bins are unchanged.

\textbf{Terminal case.} The terminal transition is a real unsafe termination recorded from the environment (reset to $\termS$, action \termA), with $R_{t+1}=\termR$ and next state $\termSn$. Because the arm is saturated in the last $\phi$ bin, $S_t$ and $S_{t+1}$ map to the \emph{same} $Q$ row (index \mbox{$s_t=s_{t+1}$} in the table). So the stored next-state rows cannot differ in the entry $Q(S_t,A_t)$: it is held at \termQsa{} in both variants, and only the other entries differ (variant 2 has very large and very different values). For a terminal transition the continuation value is zero, so $Y=R_{t+1}$ for both methods whatever values are stored for $S_{t+1}$, and both variants give the same $Q_{new}(S_t,A_t)$.
