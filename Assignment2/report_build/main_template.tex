\noindent\textbf{Note on supplied code.} The supplied \texttt{furuta\_env.py} was a balancing task (upright start, termination at $20^\circ$). I modified it in place for swing-up: downward start, wrapped $\widetilde\theta$, termination only on the arm limit, a five-second success criterion and an explicit \texttt{outcome} field, and the reward $\tfrac12(1+\cos\widetilde\theta)-0.001\tau^2$ ($-10$ on unsafe termination), which is $0$ at the bottom and $1$ upright.

\noindent\textbf{Design fix after a first run.} My first run used the reward $\cos\widetilde\theta-0.001\tau^2$. In that run the mean episode duration fell from about \oldDurFrom{} to \oldDurTo{} steps while the per-step reward stayed near $-0.87$, so the rising return curve was misleading: near the bottom every step was worth about $-1$, so with $\gamma=\cfggamma$ surviving was worth about $-100$ while crashing into the arm limit cost only $-10$, and the agent learned to crash. I therefore shifted the reward to be non-negative; all results below use the new reward. (The old-run figures are the only numbers in this report that are not read from \texttt{results/}.)

\textbf{Outside the upright region.} After one step from the start, $\widetilde\theta=\outsidedeg^\circ$ and \texttt{terminated} was false. Stronger evidence: a full episode with zero torque from the downward start ran \zeroSteps{} steps and ended \zeroOutcome{} (terminated=\zeroTerm, truncated=\zeroTrunc), so the pendulum spent the whole episode outside $|\widetilde\theta|\le20^\circ$ without terminating. Terminating there would end every episode on its first step (it starts at the bottom, $\approx180^\circ$ from upright), so the agent could never experience the swinging needed to reach the upright region.

\textbf{Upright counter reset.} In a test episode started upright, the consecutive-upright counter reached \ctrBefore{} steps, and on the step that left the region it was \ctrAfter{} with terminated=\ctrTermExit. After re-entering, it took \ctrReentry{} more steps to finish with outcome \ctrOutcome, so success requires \successsteps{} \emph{consecutive} upright steps, not a cumulative count.

\section{Epsilon-greedy verification}
Implementation: with probability $\epsilon$ sample uniformly from \emph{all} actions (greedy ones included); otherwise choose uniformly among tied greedy actions. For $Q(s^\dagger,\cdot)=[1,2,2]$ the implied probabilities are $\epsilon/3$ for action 0 and $\epsilon/3+(1-\epsilon)/2$ for actions 1 and 2. Seed \epsseed, \epsn{} samples, $Q$ unchanged:

\section{SARSA and Q-learning update audit}
\begin{center}\small\input{tables/audit}\end{center}
Both targets use the same stored transition ($\alpha=\auditalpha$, $\gamma=\auditgamma$). $Y^{\text{SARSA}}=R_{t+1}+\gamma Q(S_{t+1},A_{t+1})$ and $Y^{Q}=R_{t+1}+\gamma\max_a Q(S_{t+1},a)$; the program output matched the hand calculation (asserted in \texttt{audit\_updates.py}). The two targets are equal when the next action $A_{t+1}$ is a greedy action in $S_{t+1}$ (for example the greedy policy or $\epsilon=0$), and also whenever all $Q(S_{t+1},\cdot)$ are equal (every action is then greedy); they differ when exploration picks a non-greedy $A_{t+1}$.

\textbf{Nonterminal case.} The state index changes from the $S_t$ row to the $S_{t+1}$ row although the step is physically small, because $\widetilde\theta$ crosses the $\pm\pi$ wrap seam: the $\widetilde\theta$ bin goes from \seamFrom{} to \seamTo{} while the other three bins are unchanged.

\textbf{Terminal case.} The terminal transition is a real unsafe termination recorded from the environment (reset to $\termS$, action \termA), with $R_{t+1}=\termR$ and next state $\termSn$. Because the arm is saturated in the last $\phi$ bin, $S_t$ and $S_{t+1}$ map to the \emph{same} $Q$ row (index \mbox{$s_t=s_{t+1}$} in the table). So the stored next-state rows cannot differ in the entry $Q(S_t,A_t)$: it is held at \termQsa{} in both variants, and only the other entries differ (variant 2 has very large and very different values). For a terminal transition the continuation value is zero, so $Y=R_{t+1}$ for both methods whatever values are stored for $S_{t+1}$, and both variants give the same $Q_{new}(S_t,A_t)$.
